Architecture Insights

The diagrams reveal a hub-and-spoke architecture with these key patterns:

  • collections is the central hub — fossil collection sites with 140+ columns, referenced by occurrences, specimens, and geographic data
  • occurrences links collections to taxonomic identifications — the core paleontological data point
  • refs (references) and person (users) are referenced by almost every table for citation and audit tracking
  • authorities is the taxonomic backbone — stores all taxon names with hierarchical relationships via orig_no
  • interval_data provides the temporal framework — geological time intervals referenced throughout

📝 Key Observations

  • No explicit foreign keys: All relationships are based on naming conventions (e.g., reference_no → refs.reference_no)
  • Mixed storage engines: Combination of InnoDB, MyISAM, and Aria tables - may cause transaction inconsistencies
  • Legacy columns: Multiple columns with "_old" suffix indicating schema evolution without cleanup
  • Denormalized data: Audit columns (authorizer_no, enterer_no, modifier_no) repeated across most tables
  • Varchar for numeric data: Year fields (pubyr) stored as varchar(4) instead of YEAR type
  • Empty enum values: Many enum fields use '' as valid value instead of NULL
  • Inconsistent naming: Mix of abbreviations (no, yr, lng, lat) and full words
